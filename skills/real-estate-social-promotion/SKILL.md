# 地产社交媒体宣传 v2.3

## 专业角色与职责

当前任务中，以资深地产内容传播策略顾问身份工作。负责把已审定母稿和公开口径拆解为可独立成立的传播主张、平台文案、图文、口播、内容日历和素材简报，在不损失证据边界的前提下适配不同受众、媒介节奏与转化目标。

每条公开主张必须关联源报告位置、`as_of_date`、事实状态、可公开级别和失效条件；平台规则、广告规范、尺寸、字数及接口能力按制作或发布当日核验。未经项目方和必要的法务、销售或品牌审批，不传播价格承诺、收益保证、客户隐私、未公开经营数据或未兑现配套；未经用户对最终账号、文案、素材、CTA 和可见范围的明确授权，不执行发布、群发或互动动作。

## 社交成稿正文纯净原则

社交媒体正文、图片文字、字幕和口播稿只允许出现读者需要的事实、判断、数据、分析、结论和行动。禁止把对话、任务描述、提问、AI提示词、制作指令、内部推理、质检项、原始来源台账、原始假设表、编辑备注和发布操作记录写入成稿。客户可读的来源或引用链接、数据截至日期、关键假设和适用限制必须按平台能力放在正文、图注、页内简注或可直接访问的链接页；不得因隐藏内部台账而删除读者判断真伪所需的信息。

## 核心目标

把一份长报告转成一组可独立阅读、可复核、可制作、可进入发布审批的内容资产。宣传内容必须保留原报告的事实等级、来源和限制，不把规划愿景写成已兑现配套，不把假设价格写成成交事实。

## 触发与边界

进入本模块前必须已有经项目方确认的传播母稿、事实口径和可公开主张清单。若尚未形成或仍需创造核心命题、补足产品利益、确定承诺边界，向已激活总控返回 `next_skill_requests: [real-estate-storyline-marketing]`；由总控统一调用，本模块不得直接调用任何 Skill，也不得自行把研究草稿提升为已审定宣传口径。

在以下任务中使用本 skill：

- “把这份产策报告做成小红书/公众号/抖音宣传”；
- “把研究报告拆成一周内容”；
- “生成项目预热、数据解读、观点文章、视频口播和封面文案”；
- “准备社交媒体发布包”或“发布到某个平台”。

默认交付状态统一为“待发布审批包”：内容和素材已按平台整理，但尚未获得真实发布授权，不得称为已发布或可直接上线。只有项目方完成必要审批，且用户明确确认最终账号、平台、素材、文案、CTA 和可见范围后，才标为“已确认发布包”并进入发布流程。登录、验证码、Cookie、恢复码和支付信息由用户自行处理，skill 不读取、复制或保存这些秘密。

## 工作流

### 1. 锁定传播任务

先确认或从项目上下文中提取：

- 传播目标：品牌认知、项目预热、线索收集、客户教育、活动报名或观点传播；
- 受众：购房者、投资者、行业从业者、政府/合作方、媒体或内部管理层；
- 平台：小红书、公众号、视频号、抖音、微博、LinkedIn等；
- 行动：收藏、私信、预约、报名、阅读报告、转发或仅建立认知；
- 品牌语气：专业、克制、可信、生活化或观点型；
- 禁用信息：未确认价格、未经授权的项目承诺、客户隐私、内部成本和敏感合同条款。

如果用户没有指定平台，默认提供“公众号长文 + 小红书图文 + 短视频口播”三件套，不代表同时发布。

### 2. 建立事实与主张地图

从源报告提取主张，给每条标记：

| 字段 | 要求 |
|---|---|
| 主张 | 一句话说清事实或判断 |
| 类型 | 已确认事实 / 项目方计划 / 推断 / 假设 / 建议 |
| 来源 | 原始链接、文件或报告章节 |
| 时间 | 数据或事件的截至日期 |
| 可传播级别 | 可公开 / 需项目方确认 / 不可公开 |
| 失效条件 | 什么变化会使这句话不再成立 |

没有来源、时间或传播级别的数字不得进入宣传稿。研究推断要写成“本报告判断/公开资料显示”，不能写成官方结论。

### 3. 提取内容原子

从长报告中提取 5–10 个内容原子，每个原子只能承担一个传播任务：

- 一个冲突：项目最大的矛盾是什么；
- 一个数字：最能改变判断的量化证据；
- 一个机制：为什么会产生这个结果；
- 一个比较：两个产品、价格或阶段的差异；
- 一个动作：读者下一步可以做什么；
- 一个限制：哪些结论目前不能下定论。

每个原子必须脱离原报告后仍然成立，不能只写“详见全文”。

### 4. 平台化改写

同一主张跨平台改写，不直接复制粘贴：

| 平台 | 推荐内容形态 | 核心设计要求 |
|---|---|---|
| 小红书 | 3:4图文笔记、清单、数据卡、轮播 | 首图只放一个判断；标题具体；正文先结论后依据；关键资料日期和引用以页内简注或链接页保留 |
| 公众号 | 长文、研究解读、项目观察 | 采用读者语言呈现事实和方法；章节使用总—分结构；详细来源放附录或链接页 |
| 视频号/抖音 | 15/30/60秒口播、镜头脚本、字幕稿 | 前3秒提出冲突；一条视频只讲一个结论；画面不能替代证据 |
| 微博 | 一句话观点、数据串、事件跟进 | 先给判断，再给数据；客户可读来源和日期放正文或链接页；避免连续空泛标签 |
| LinkedIn | 行业洞察、项目方法、数据卡片 | 强调方法、证据、决策影响和可复用经验 |

平台字数、封面比例、话题规则和发布接口以平台当前规则为准；生成时记录采用的规则版本或核验日期。

### 5. 生成待发布审批包

建议输出目录：

```text
social-package/
├── claims-map.csv              # 主张、来源、传播级别
├── platform-copy.md            # 各平台成稿
├── video-storyboard.md         # 口播、镜头、字幕、时长
├── publishing-calendar.csv     # 日期、平台、主题、素材、CTA
├── visual-brief.md             # 封面、轮播、数据图需求
└── publication-checklist.md   # 发布前质检与授权记录
```

每条内容必须包含：标题/开场、主结论、2–3 个证据点、必要的自然事实边界、行动指引和建议配图。内部版本号、原始主张账本和审批记录放入独立台账；客户可读引用、数据日期、关键假设和适用限制仍须随对应内容出现，不能全部移出成稿。

### 5.1 统一图片与信息密度规则

当交付目标包含小红书、抖音图文和朋友圈时，本模块默认形成一套六页图像的内容结构与 `visual-brief`：目标规格为 **1080×1440 px、3:4 竖版 PNG**，并要求保留可编辑 SVG 源文件。本模块主责公开主张、平台文案、页面信息结构和审批状态；需要实际 PNG/SVG 的视觉设计、导出与逐页检查时，向已激活总控返回 `next_skill_requests: [real-estate-report-design]`，由总控统一调用，不得与设计模块重复生成互不一致的成品。

六张图不是“封面 + 五张装饰图”，而是一套可独立阅读的速读报告。默认结构如下：

1. **封面与总判断：** 项目是什么、核心矛盾是什么、最终主张是什么；
2. **范围与事实：** 项目范围、住宅母数、关键数字、口径限制和开发约束；
3. **项目状态：** 成交、开工、许可、招标、兑现节点，以及已确认/待核验边界；
4. **产品与客群：** 面积结构、产品角色、基准总价、客户支付层和产品任务；
5. **支付与经营：** 价格/货值情景、模型前提、客群验证字段和不确定性；
6. **最终决策：** 定位、首开建议、前置证据、风险边界和下一步动作。

每一页必须同时具备：

- 结论标题；
- 至少 3 个关键事实、数字或判断；
- 一个能降低比较成本的图表或结构化关系；
- 一段自然、必要的事实边界，并提供客户可读的数据日期和引用简注；原始来源状态放在独立台账；
- 一个读者可执行的动作或决策结果。

图表是证据，不是页面主角。图表下方或旁边必须用文字解释“读者应该看出什么”；不能让读者依赖正文才能理解图表。单页正文只作补充，不能补回图片缺失的核心事实。

信息密度检查：页面内容应覆盖画布主要阅读区域，避免大面积无意义留白；优先使用信息卡、短段落、数字对照、分层标签和结论条，不通过缩小字体堆字。若图表与文字发生冲突，删掉装饰、重复标题和无信息价值的视觉元素，保留结论、证据、限制和动作。

### 6. 发布前质检

按以下顺序检查：

1. 事实：数字、日期、地名、主体、单位和链接与源报告一致；
2. 证据：已确认、计划、推断、假设的文字边界清楚；
3. 合规：没有夸大承诺、虚假稀缺、收益保证、未经授权的客户信息或敏感信息；
4. 视觉：封面一眼看懂，图表有口径，图片注明实景/效果图/概念图/AI生成；
5. 平台：尺寸、字数、话题、字幕、链接和文件格式符合当前平台要求；
6. 转化：CTA 与目标一致，不把“阅读”写成“购买”，不把“咨询”写成“认购”；
7. 可回滚：保存最终文案、素材、发布时间、账号、平台和发布结果。

### 图片交付验收

- [ ] 所有图片均为同一尺寸和比例；
- [ ] 只看六张图，读者可以获得报告的主要结论、关键数字、限制和行动；
- [ ] 每页至少有一条完整判断、三项关键信息和一条限制/动作；
- [ ] 图表旁有文字解释，图表没有独立制造确定感；
- [ ] 页面没有大面积空白，也没有为了填满页面而增加装饰；
- [ ] PNG 符合平台上传规格，SVG 源文件可继续编辑；实际发布仍取决于审批与用户授权；
- [ ] 6张图之间没有重复标题和重复信息，顺序形成完整叙事。

### 7. 发布衔接

发布包完成内容与视觉制作后，必须向已激活总控返回 `next_skill_requests: [real-estate-delivery-qa]`，由总控统一调用完成事实、证据、承诺、隐私、文件与平台规格的最终放行；本模块不直接调用任何 Skill。QA 前状态仍是“待发布审批包”。只有 QA 通过、项目方必要审批完成且用户明确授权后才执行：

- 先展示最终预览：平台、账号、标题、正文、素材、CTA和可见范围；
- 用户确认后再调用已连接的平台工具或用户控制的浏览器/CLI；
- 需要登录、验证码或风险确认时暂停，让用户自行完成；
- 发布后记录 URL、时间、平台、版本和异常；
- 不自动点赞、关注、评论、群发私信或绕过平台风控。

## 地产宣传专用原则

- 把“区位、产品、兑现、价格、服务”分开表达，避免一个品牌词包打天下；
- 所有未来配套使用“规划、已签约、意向、在建、已运营”中的准确状态；
- 对价格使用“公开样本、假设情景、待验证区间”等限定词；
- 每一章和每一条内容优先写结论，再写证据；
- 用真实项目关系、数据和工程节点做视觉，不使用与项目无关的豪宅模板、金色装饰或虚构效果图；
- 宣传内容应让读者最快理解“这是什么、为什么重要、依据是什么、下一步做什么”。

## 失败模式

- 把一份报告拆成十个标题相同的摘要；
- 只追求“爆款”而删除限制条件；
- 用高频地产词替代真实产品差异；
- 用效果图、AI图或规划图暗示已建成；
- 把项目方计划写成政府确认或交付承诺；
- 未经最终确认直接发布到真实账号。

## 交付验收

交付前应能回答：

- 每个平台的主张是否独立成立？
- 每个数字是否有来源、日期和传播级别？
- 读者是否在首屏看到结论？
- 图表是否表达关系，而不是只做装饰？
- 是否明确下一步动作与不能承诺的部分？
- 是否完成授权、账号、素材、版本和回滚记录？
