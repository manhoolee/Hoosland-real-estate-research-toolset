# 引导式交互与项目状态

## 项目状态对象

```json
{
  "version": "2.1.0",
  "project_name": "",
  "scope_id": "",
  "stage": "",
  "business_objective": [],
  "as_of_date": "YYYY-MM-DD",
  "research_mode": "rapid|standard|audit",
  "status": "exploring|analyzing|reviewing|complete",
  "confirmed_facts": [],
  "assumptions": [],
  "open_questions": [],
  "decisions": [],
  "next_actions": []
}
```

## 对话协议

- 先复用用户已经给出的信息，不重复问。
- 每轮最多问 3 个会改变结论的问题，并说明不回答时采用什么默认假设。
- 用户输入编号时执行对应动作；用户自由输入时先识别它更新了事实、假设、目标还是决策。
- 每轮至少推进一个可见成果：范围表、竞品条目、假设卡、测算或结论修订。
- 只有存在未决工作时提供 2–4 个下一步动作；推荐项必须解释推荐理由。
- 用户明确要求“直接形成报告”时，基于现有证据交付，并把缺口写入限制条件，不以问卷阻断。

## 初级用户语言

首次出现专业术语时用一句普通话解释。例如：

- 可售率：计容面积中最终能卖给客户的比例；
- 去化：一定时间内卖掉的套数或货值比例；
- 支付边界：客户能实际承担的首付、月供和总价上限；
- 失效信号：一旦出现，就说明当前策略需要调整的可观察指标。

## 完成条件

任务状态为 `complete` 且用户要求的文件已验证时，不再机械给动作菜单。可用一句话列出非必需扩展，例如“如需，我还可以继续转成汇报 PPT”。
