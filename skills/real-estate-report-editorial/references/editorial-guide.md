# 报告文案编辑检查表

## 管理层摘要

- 一句话结论：包含范围、阶段、主矛盾和方向；
- 关键判断：每条有证据等级、前提和失效信号；
- 管理层待决策：写成具体选择，不写成泛泛“加强推进”；
- 限制条件：明确不能支持的判断，例如利润、现金流或最终售价。

## 语言检查

- 事实用“已确认/文件显示”；
- 推断用“说明/可能意味着”；
- 假设用“暂取/待验证”；
- 建议用“建议/可先测试”；
- 避免“必然、确定、领先、稀缺、世界级”等无证据表达；
- 首次出现“可售率、去化、支付边界、NPS”等术语时解释。

## 编辑质感

- 开头从具体项目矛盾进入，不从“随着时代发展”开始；
- 每个章节只保留一个主问题，避免把研究、策略和宣传混成一段；
- 用具体数字、动作和条件替代形容词；
- 用有节奏的段落和小标题制造阅读推进，不用连续粗体和感叹句制造重点；
- 结尾回到经营目标和决策动作，不用口号式收束。

## 章节顺序

执行摘要 → 范围与口径 → 事实底盘 → 市场/竞品/客群 → 产品/价格/节奏 → 营销/社群 → 财务或去化敏感性 → 风险与失效信号 → 来源、假设及待验证清单。

最后一章面向读者呈现可核验引用、数据日期、关键假设与限制，不直接倾倒内部来源账本、主张账本或编辑记录。

## 每章写作模板

```text
本章结论：用一句话先回答问题。

重点信息：
1. 最重要的事实或数字
2. 对项目的影响
3. 建议动作或限制

详细依据：展开证据、公式、假设、案例和来源。

本章收束：说明是否需要决策、核验或继续阅读。
```

目标是让读者只阅读“本章结论 + 重点信息”也能完成一次有效判断；细节用于复核，不用于隐藏结论。
