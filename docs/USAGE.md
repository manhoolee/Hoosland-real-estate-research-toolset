# 使用说明

## 1. 适用场景

工作台适合地产项目投前、投后、定位、首开、在售、存量盘活和复盘阶段，重点覆盖：

- 城市、规划、土地、市场、竞品与客群研究；
- 产品定位、面积、户配、价格、货值与推售节奏；
- 品牌故事、营销、社群和传播审批包；
- 管理层报告的编辑、设计、PDF 技术质检与最终 QA。

Skill 是方法和质量规范，不替代法律、规划、工程、财务或投资专业复核。

## 2. 本地启动

完整的平台范围、依赖安装、WSL2 与单进程演示方式见[安装指南](INSTALLATION.md)。当前完整 Harness runtime 不支持原生 Windows，Windows 用户应使用 WSL2。

### 首次安装

```bash
cd frontend
npm ci

cd ../backend
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

复制 `backend/.env.example` 为不会提交的 `backend/.env.local`，至少填写：

```dotenv
APP_ENV=development
APP_SLOT=local
PORT=8000
HARNESS_SKILL_DIRS=/absolute/path/to/repository/skills
DEEPSEEK_API_KEY=
CAPABILITY_MCP_URL=http://127.0.0.1:8000/mcp
```

启动后端：

```bash
cd backend
. .venv/bin/activate
python -m uvicorn app.main:app \
  --host 127.0.0.1 \
  --port 8000 \
  --workers 1 \
  --env-file .env.local
```

另一终端启动前端：

```bash
cd frontend
npm run dev
```

访问 <http://127.0.0.1:5173>。

> `PORT` 必须与 Uvicorn 端口一致，或显式设置匹配的 `CAPABILITY_MCP_URL`。当前实现必须使用一个 worker。

## 3. 建立一个有效任务

首条消息可以直接描述问题，系统会自动建立项目；也可以先“新建项目”，再在同一项目下建立多个对话。

最好提供以下六项：

| 字段 | 示例 | 作用 |
|---|---|---|
| `project_name` | 广州某综合体 | 项目身份 |
| `scope_id` | 一期住宅 A 地块 | 避免跨地块、期次混算 |
| `stage` | 定位 / 首开 / 在售 | 选择分析流程 |
| `business_objective` | 保去化、兼顾货值 | 明确策略取舍 |
| `as_of_date` | 2026-08-25 | 锁定研究时点 |
| `research_mode` | 快速 / 标准 / 审计 | 决定证据和复核深度 |

### 三种研究深度

- **快速**：初筛方向、机会、风险和资料缺口；
- **标准**：产策讨论，交叉核验规划、市场、竞品、客群与产品假设；
- **审计**：投决、重大调价或归档，建立逐项来源、冲突、计算底稿和人工复核状态。

## 4. 上传资料

可在当前对话上传市场报告、规划文件、价格表、表格、户型图、PDF、文本和图片，并在消息中说明：

1. 要读取哪些附件；
2. 附件属于哪个项目、期次和日期；
3. 要解决的决策问题；
4. 期望成果格式。

本地抽取明确覆盖文本、Markdown、JSON、CSV、HTML 和 PDF。Office 深度抽取、Word/PPT/Excel 交付取决于具体 Provider 或运行环境，不应默认视为开箱能力。

## 5. 任务清单与成果复核

每次发送需求后，消息内会出现两组清单：

- **任务清单**：本轮需要执行的具体工作；
- **成果要求**：需要在回复或成果区实际交付并复核的结果。

清单按“待处理 → 进行中 → 已完成”逐项更新。研究助手必须先建立初始清单，后续每次最多完成一项，不能在结尾一次性把整表补成完成。只有执行结果已经复核的项目才会显示已完成；停止、失败或正常结束时仍未完成或未复核的项目会明确显示为未完成。文件成果还会与本轮正式 `outputs` 目录中实际新增或更新的格式核对，因此模型只在文字中声称“已生成”不会把该要求变绿。自动文件证据只核对扩展名和本轮非空变化，不替代逐文件内容验收；同一扩展名的多个成果会合并为一个成果要求。

刷新页面不会重置清单。每次运行使用独立快照，重试不会拿上一轮的清单冒充当前进度。

## 6. 输出与正式交付

地产研究、项目分析、策划方案和管理报告的主成果在未指定格式时，默认生成并检查：

- Markdown；
- 独立、离线可打开的 HTML。

纯澄清、简短问答、明确不要文件，以及微信归档、社交素材、数据模型等有专项输出契约的任务不强制双格式；如果专项任务同时要求形成主报告，主报告部分仍适用上述默认。

需要 PDF 时请明确写“生成 PDF 并完成逐页技术检查”。正式链路是：

```text
综合地产总控 → 业务责任专项 → 报告编辑 → 报告设计 → 按需 PDF → 最终交付 QA
```

PDF 模块只验证转换、页数、文本提取和逐页渲染；它不能替代业务事实、版权、隐私和发布条件的最终放行。

## 7. 示例请求

### 综合研判

```text
请按标准模式研判广州某项目，一期住宅 A 地块，研究截至 2026-08-25。
重点回答客群、产品、价格和首开节奏，并输出 Markdown 与独立 HTML。
```

### 资料核查

```text
比较这两份市场报告，列出统计口径差异、冲突数据、对当前判断的影响，
以及需要回查的原始来源。不要静默选择其中一份。
```

### 产品测算

```text
基于已确认的住宅可售面积、产品段占比和三档价格，生成可复算的货值敏感性分析。
所有输入、单位、公式、舍入、假设和失效条件单列。
```

### 正式报告

```text
把已完成研究整理为管理层正式报告，依次完成编辑、设计和交付 QA。
客户正文不要出现提示词、工作流、调试信息或内部质检台账。
```

### PDF

```text
基于这份已审定 HTML 生成 PDF，逐页渲染检查。
技术质检记录放在工作区，不要写入客户正文；完成后继续移交最终交付 QA。
```

### 传播审批包

```text
基于这份已审定母稿生成公众号、小红书和短视频待发布审批包。
保持数据口径和风险边界，不执行真实发布。
```

## 8. 运行、刷新、停止和重试

- 任务运行中可以刷新页面；后台任务不会依赖原 SSE 连接继续存在；
- 页面会读取运行状态并在完成后自动回填唯一结果；
- 页面会同步恢复本轮任务与成果要求的最新 revision，终态继续显示已完成和未完成项；
- 不要因刷新而重复发送同一请求；
- “停止”会请求取消当前任务；
- 失败后的重试引用原消息和原附件，不追加重复用户消息；
- 多标签页发生竞态时，前端以服务端状态为准进行对账。

## 9. 管理配置

历史项目和 Provider 配置需要管理员登录。启用后台至少需要：

- `ADMIN_PASSWORD`
- `ADMIN_SESSION_SECRET`

Provider 密钥保存后不会由 API 明文返回。生产 HTTPS 必须设置 `ADMIN_COOKIE_SECURE=true`。完整配置见 [配置参考](CONFIGURATION.md)。

## 10. 能力状态

右侧能力面板会显示主 Agent、搜索、视觉、文档、PDF 等状态。可选能力未配置时会返回明确错误；不要把“未配置”“尚未调用”“调用失败”写成已完成。

健康检查：

```bash
curl http://127.0.0.1:8000/api/health/live
curl http://127.0.0.1:8000/api/health/ready
curl http://127.0.0.1:8000/api/capabilities
```

## 11. 成果文件

最终文件位于当前 conversation 的 `workspace/outputs`，可在成果区打开或下载。`work` 中的底稿、预览图和内部 QA 记录不是正式成品，不能直接对外提交。
